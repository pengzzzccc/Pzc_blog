## **1. 核心研究目标与解耦系统架构**

在现代开放世界与沙盒游戏工业管线中，技术美术与关卡策划通常依赖随机种子和程序化参数来快速构建宏观基础地形，而非完全手工雕琢。**PTG** 的核心工程目标是探索：**基于 Unity 6 构建的伪随机种子驱动多重分形地形系统，能否在保持严格逐位确定性复现的前提下，将单次完整重建控制在 60 帧单帧预算（16.7 毫秒）以内，并让非工程背景的创作者无需程序员指导即可直观理解、预测并操控复杂噪声与着色参数。**

为此，我将系统设计为三层高内聚、低耦合的架构：
- **纯 C# 数学与算法核心**：完全剥离引擎 API 与第三方开源库依赖，从底层独立实现高质量伪随机数发生器、多维梯度噪声置换表以及多重分形反馈算法。在自主重构置换表与晶格点积计算的过程中，我独立排查并修复了早期纵轴梯度未传入点积运算导致地形出现方向性拉伸的深层缺陷，使生成的地表恢复各向同性的自然质感。
- **动态 32 位网格拓扑与宏观星球拼接**：支持平面大陆、环形衰减岛屿以及由三维噪声驱动的六面体投影立方球行星三种宏观拓扑。当网格分辨率提升至 256×256 以上时，系统自动将 Unity 默认的 16 位索引缓冲区升级为 32 位索引格式，突破单网格 65,535 顶点的硬件寻址限制；同时在立方球行星的六个面交界处实现了共享边界顶点法线平均焊接，彻底消除了星球表面拼接处的黑色光照接缝。
- **UI Toolkit 双栏交互界面与输入焦点隔离**：采用左侧噪声与拓扑控制、右侧八层高度与坡度着色面板的双栏布局，配备自研内置 HSV 拾色器、单色偏移着色器驱动的三态线框叠加视图以及全参数通俗化悬停提示；并在界面根节点实现导航事件拦截与输入状态锁定，根除了在输入框打字或拖拽滑块时按键穿透导致自由飞行相机乱飞的问题。

## **2. 数据驱动的性能剖析与 13.8 至 15.0 倍多核并行加速**

为了避免凭主观经验盲目优化，我首先开发了内置低开销分段性能遥测模块与独立离线网页对比看板，在 16 个测试会话中采集了 174 次地形生成的各阶段中位耗时数据。

早期基线数据暴露出三个严重的性能瓶颈：全图高度计算、网格几何体装配，以及高达 161.1 毫秒的无意义网格碰撞体烘焙。针对量化瓶颈，我实施了三步架构优化：
- **移除冗余碰撞体烘焙**：剔除实时滑块预览阶段不必要的物理碰撞体生成开销。
- **建立高度矩阵缓存与快速重着色通道**：当用户仅调节右侧八层地表颜色或坡度阈值时，系统直接跳过高度计算与网格拓扑重建，复用缓存的高度矩阵仅更新顶点颜色。在 257×257 分辨率下重着色仅需 **0.8 至 1.9 毫秒**，在 513×513 分辨率下仅需 **5.1 毫秒**。
- **基于多核并行的行级矩阵加速**：将高度图求值、网格顶点装配与顶点颜色计算改造为无锁行级多线程并行执行。

| **管线阶段** | **基线 (257²)** | **多核并行优化后 (257²)** | **基线 (513²)** | **多核并行优化后 (513²)** |
|---|---|---|---|---|
| **高度图计算** | 58.4 ms | **4.8 ms** | 226.2 ms | **14.3 ms** |
| **网格几何体装配** | 46.2 ms | **1.1 ms** | 194.5 ms | **3.5 ms** |
| **顶点颜色计算** | 5.8 ms | **1.7 ms** | 23.4 ms | **6.1 ms** |
| **GPU 缓冲区上传** | 1.8 ms | **1.5 ms** | 9.4 ms | **9.1 ms** |
| **法线与包围盒重算** | 2.1 ms | **1.4 ms** | 5.8 ms | **6.5 ms** |
| **碰撞体烘焙** | 30.5 ms | **已移除** | 161.1 ms | **已移除** |
| **中位总生成耗时** | **144.8 ms** | **10.5 ms** | **593.4 ms** | **39.5 ms** |
| **实测加速比** | 1.0x | **13.79x** | 1.0x | **15.02x** |

优化后，257×257 标准分辨率（约 66,049 个顶点）的总生成时间从 **144.8 毫秒降至 10.5 毫秒**，完全控制在 60 帧单帧预算（16.7 毫秒）以内，拖拽滑块实时塑形的流畅度如同直接使用画笔；513×513 超高分辨率（约 263,169 个顶点）也从近 **600 毫秒降至 39.5 毫秒**。同时，遥测数据清晰表明在 513×513 下 CPU 端网格生成仅需 3.5 毫秒，而 CPU 向 GPU 上传顶点缓冲区耗时 9.1 毫秒已成为新的首要瓶颈，为后续向 GPU 计算着色器管线演进提供了确凿的数据依据。

## **3. 49 项自动化单元测试与两轮用户可用性闭环迭代**

为了在引入多线程加速的同时严守确定性底线，我编写了 **49 项编辑器自动化单元测试**，全面覆盖随机数分布特性、晶格边界、哈希种子复现、分形能量响应、岛屿衰减与球体顶点预算分配，并通过黄金标准一致性测试证实：**多线程并行生成的顶点坐标、UV、高度矩阵与顶点颜色同单线程串行计算在每一个网格顶点上均保持逐位完全一致。**

在工作流可用性评估方面，我使用 Windows 独立构建包组织了两轮真实用户测试（共 7 名有效受试者，其中 71.4% 无程序化生成工具使用经验）：
- **量化可用性评分**：在 10 分制量表中，**界面清晰度获得 8.00 / 10 分**，**参数易懂度获得 7.14 / 10 分（标准差仅 0.38）**。在高山湖泊、峡湾地貌与蓝色星球三项无指导逆向地形还原任务中，测试者均能准确把握分形层数、阶地化与高度缩放规律并收敛至目标区间。
- **用户反馈驱动的敏捷迭代证据链**：第一轮与第二轮测试者提出的全部六项核心痛点，均直接驱动了工程功能的落地——包括新增三态线框视图与悬停说明、自研内置 HSV 拾色器、将所有预设底层算法统一至多重分形管线以确保每个滑块在任意预设下均有即时视觉反馈、新增全局快捷键一键隐藏界面以便全景观察，以及新增环形岛屿与六面体立方球行星宏观拓扑切换。
